## Story

**As a** gestor de tráfego operando uma Manager Account (MCC) Google Ads,
**I want** o comando `google-ads accounts --tree` que expande automaticamente as contas filhas da MCC,
**so that** eu possa identificar e configurar uma conta cliente como default sem sair da CLI (e destravar `report`/`optimize`/`publish` do squad `traffic-google`).

## Context

Quarta story do épico `epic-5-google-ads-agent`. Stories 5.1, 5.2, 5.3 estão **Done** e a CLI tem `auth`, `accounts`, `config`, `report`. O squad `traffic-google` foi criado mas ESTÁ BLOQUEADO em uso operacional porque:

1. A única conta acessível via `listAccessibleCustomers` é `1528041123` ("Solaro Marketing e Vendas")
2. Essa conta é uma **Manager Account (MCC)**
3. Google Ads API **rejeita métricas em MCC** por design (`REQUESTED_METRICS_FOR_MANAGER`)
4. Para destravar, é preciso configurar uma **conta cliente** (sub-conta filha da MCC) como `customer-id` default
5. `listAccessibleCustomers` NÃO retorna as contas filhas da MCC — só o nó raiz

Esta story adiciona o comando que expande a árvore MCC → filhas via GAQL.

**Descoberta operacional:** Esta story foi escopada após a primeira execução real do squad `traffic-google` (via `*accounts` no Campaign Publisher), quando o blocker apareceu de forma concreta.

**O que NÃO faz parte:**
- Recursão profunda de MCC-of-MCC (>3 níveis — raro)
- Filtros por status no output (CLI retorna tudo; usuário filtra no UI)
- Pagination (MCCs raramente excedem 100 filhas)
- Mutações em contas filhas — leitura apenas

## Acceptance Criteria

1. Flag `--tree` adicionada ao comando `google-ads accounts` (`src/cli/commands/accounts.ts`)
2. Quando `--tree` é usada, comando expande contas filhas de cada accessibleCustomer que for MCC via GAQL contra `FROM customer_client`
3. Atributos retornados pela expansão: `customer_client.id`, `customer_client.descriptive_name`, `customer_client.level`, `customer_client.manager` (boolean), `customer_client.currency_code`, `customer_client.status`
4. Para contas accessibleCustomer que NÃO são MCC, expansão é skipada (sem hit de API desnecessário) e a conta aparece como raiz sem filhas
5. Output em modo `table` (default): indentação por `level` com símbolos visuais (`├──` `└──` para tree), colunas `ID | Nome | Moeda | Status | Manager?`
6. Output em modo `--format json`: array plano de objetos com keys `customerId`, `name`, `currencyCode`, `status`, `level` (número), `isManager` (boolean), `parentId` (string ou null)
7. Resource names do tipo `customers/1234567890` são despeladas para apenas `1234567890` antes de emissão (parser helper `stripCustomersPrefix`)
8. Quando `--tree` é rodada e nenhuma MCC é encontrada no nível raiz, output mostra warning amigável em PT-BR (não bloqueia)
9. Quando MCC tem 0 contas filhas, output mostra mensagem orientando criar conta cliente no UI (não erro)
10. Boundary rule respeitada — nova função `listMccTree` continua dentro de `src/google-ads-api/accounts.ts` (único arquivo que importa o SDK)
11. Testes unitários:
    - `formatTree` (puro — testa renderização de tree mock com 3 níveis)
    - `stripCustomersPrefix` (helper de string)
    - GAQL builder para `customer_client` (sem hit de rede)
    - Coverage ≥80% nos arquivos novos/modificados
12. Smoke real-time: `google-ads accounts --tree` rodado contra MCC `1528041123` retorna pelo menos 1 conta cliente filha (Solaro deve ter ao menos 1 sub-account, dado que o usuário já vinha rodando campanhas Meta — provavelmente tem cliente Google também)

## Dev Notes

### Referência meta-ads (sem equivalente)

`meta-ads-agent` não tem o conceito de MCC nem este comando. Feature é específica do Google Ads. Tudo é original.

### SDK signature (já está dentro do boundary)

```ts
import { GoogleAdsApi } from 'google-ads-api';

const customer = client.Customer({
  customer_id: stripDashes(mccId),
  login_customer_id: stripDashes(mccId), // MCC IS the login context here
  refresh_token,
});

const rows = await customer.query(`
  SELECT
    customer_client.id,
    customer_client.descriptive_name,
    customer_client.level,
    customer_client.manager,
    customer_client.currency_code,
    customer_client.status,
    customer_client.client_customer
  FROM customer_client
`);
```

Cada row tem shape:

```ts
{
  customer_client: {
    id: '...',                   // long integer as string
    descriptive_name: '...',
    level: 0 | 1 | 2 | ...,       // 0 = self (MCC), 1 = direct child, etc
    manager: true | false,
    currency_code: 'BRL' | 'USD' | ...,
    status: 'ENABLED' | 'CANCELED' | ...,
    client_customer: 'customers/1234567890',  // PRECISA stripCustomersPrefix
  }
}
```

### Como detectar se uma conta é MCC

Opção A (preferida — sem query adicional): Usa `listMccTree` em TODAS as accessibleCustomers; se retornar level=0 com manager=true e sem filhas adicionais, era MCC vazia; se retornar erro CUSTOMER_NOT_MCC, era conta cliente. Try/catch elegante.

Opção B (uma query extra por conta — mais lento): `SELECT customer.manager FROM customer LIMIT 1` na conta, se manager=true → é MCC.

**Recomendação:** Opção A para MVP (menos queries). Try `listMccTree`; se erro `CUSTOMER_NOT_MCC` ou similar → registrar a conta como folha sem expandir. Catch silencioso por conta.

### Decisões técnicas tomadas
1. **Opção A (try/catch) escolhida** conforme recomendação @sm — try `listMccTree` em todas; catch silencioso vira nó folha. Funcionou perfeitamente no smoke (MCC Solaro expandiu; contas não-MCC viriam como folha caso existissem).
2. **Sort estável** das tree nodes: `level ASC, then name ASC`. Output determinístico mesmo entre runs.
3. **Merge metadata**: ao montar tree, nome/moeda/status enriched do `listAccessibleCustomersDetailed` sobrescrevem o nó raiz da MCC (que veio do GAQL customer_client) — pois o GAQL pode retornar metadata reduzida.
4. **Algoritmo `isLastAtLevel`**: look-ahead pela array; encontra próximo nó mesmo level antes de encontrar level inferior. Funcional para tree de qualquer profundidade.
5. **Mensagem orientativa explícita** "NÃO use a MCC — métricas falham" no rodapé — feedback direto ao usuário ANTES de ele tentar `set-default` na MCC e bater no veto da Story 5.3.
