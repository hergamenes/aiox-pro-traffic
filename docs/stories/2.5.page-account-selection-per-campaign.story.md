## Story

**As a** gestor de tráfego,
**I want** poder escolher qual página do Facebook usar ao criar uma campanha,
**so that** eu possa gerenciar campanhas de diferentes páginas/clientes.

## Acceptance Criteria

1. Nos comandos `create sales` e `create leads`, flag opcional `--page` permite selecionar página diferente da padrão
2. Se `--page` não informado, usa a página padrão configurada na Story 1.3
3. Se múltiplas páginas e nenhuma padrão definida, exibe lista numerada para seleção interativa
4. Valida que a página selecionada tem Instagram conectado antes de criar anúncio com posicionamento Instagram
5. Atualiza o anúncio com a página e Instagram corretos

## Dev Notes

### Previous Story Insights (Story 2.4)

- CLI commands use `readline/promises` for interactive prompts (zero deps, ESM compatible) — reuse same approach for page selection prompt
- `salesCommand` and `leadsCommand` currently hardcode `config.defaults.pageId` and `config.defaults.instagramAccountId` at `src/cli/commands/create.ts`
- Both commands early-exit if `pageId` is null — this logic moves to the page-resolver
- Orchestrator receives `pageId` and `instagramAccountId` via `CampaignConfig` — no orchestrator changes needed
- Strategy `getAdParams` already handles `instagramAccountId: null` gracefully (omits `instagram_actor_id` from `object_story_spec`)

### Existing Code to Reuse [Source: docs/architecture.md#Components]

- **`adapter.listPages()`** at `src/meta-api/adapter.ts:127` — Returns `Page[]` with `{ id, name, category, instagramAccountId }`. Already implemented in Story 1.3.
- **`adapter.getInstagramAccount(pageId)`** at `src/meta-api/adapter.ts:160` — Returns `InstagramAccount | null` for a given pageId. Already implemented in Story 1.3.
- **`readline/promises`** — Used in `create.ts` for interactive prompts. Same approach for page selection.
- **`formatTable()`** at `src/cli/display.ts` — For displaying page list in numbered format.

### Data Model Context [Source: docs/architecture.md#Data Models]

- `AppConfig.defaults.pageId: string | null` — Default page ID from `~/.meta-ads/config.yaml`
- `AppConfig.defaults.instagramAccountId: string | null` — Default Instagram ID
- `CampaignConfig.pageId: string` — Required for campaign creation (must be resolved before orchestrator)
- `CampaignConfig.instagramAccountId: string | null` — Optional, used for Instagram placement in ad

### Page Type from Adapter [Source: src/meta-api/types.ts]

```typescript
interface Page {
  id: string;
  name: string;
  category: string;
  instagramAccountId: string | null;
}
```

### CLI Architecture [Source: docs/architecture.md#CLI Layer]

- `commander` options: `.option('--page <pageId>', 'description')` — adds flag to command
- Access via `options.page` in action handler (commander provides `options` object)
- `salesCommand` and `leadsCommand` use `.action(async (nameArg?, options?) => { ... })` — need to add `options` parameter if not already present

### Key Implementation Notes

- **DO NOT modify the orchestrator** — page resolution happens BEFORE the orchestrator call, in the CLI layer
- **DO NOT modify CampaignConfig type** — it already has `pageId: string` and `instagramAccountId: string | null`
- **DO NOT modify strategies** — they already handle `instagramAccountId: null` correctly
- `--page` flag is optional — commander will set `options.page = undefined` when not provided
- Interactive page selection should match the pattern used by `meta-ads pages` command (numbered list)
