## Story

**As a** gestor de tráfego,
**I want** criar uma campanha de Vendas com objetivo de Compra via comando,
**so that** eu possa subir campanhas de vendas sem usar o Gerenciador de Anúncios.

## Acceptance Criteria

1. Comando `meta-ads create sales` inicia fluxo de criação de campanha de Vendas
2. Sistema solicita: nome do anúncio, orçamento diário (R$), textos (título, texto principal, descrição, URL do site)
3. Cria campanha com objetivo `OUTCOME_SALES` e optimization goal `OFFSITE_CONVERSIONS` evento `PURCHASE`
4. Cria ad set com Advantage+ audience (targeting automático), orçamento diário informado
5. Cria ad com criativo da pasta, textos fornecidos, página do Facebook e Instagram padrão
6. Aplica nomenclatura automática: `PPT_VENDAS_COMPRA_[DD-MM-AA]_[NOME]`
7. Ativa a campanha (status `ACTIVE`) automaticamente
8. Exibe resumo final: nome, ID, orçamento, criativo usado, link para Gerenciador de Anúncios
9. Testes de integração cobrindo fluxo completo com mocks

## Dev Notes

### Campaign Architecture [Source: docs/architecture.md#Components]

The Campaign Orchestrator (`src/campaign/orchestrator.ts`) manages the full campaign creation pipeline. It uses the Strategy pattern for different campaign types (sales vs leads).

Pipeline: validate → upload → createCampaign → createAdSet → createAd → activate

Key interface: `createCampaign(config: CampaignConfig, bundle: CreativeBundle): Promise<CampaignResult>`

[Source: docs/architecture.md#Campaign Orchestrator]

### Meta API Campaign Endpoints [Source: docs/architecture.md#External APIs]

| Method | Endpoint | Purpose |
|--------|----------|---------|
| `POST` | `/act_{id}/campaigns` | Create campaign |
| `POST` | `/act_{id}/adsets` | Create ad set |
| `POST` | `/act_{id}/ads` | Create ad |
| `POST` | `/{campaign-id}` | Update campaign status (ACTIVE) |

Base URL: `https://graph.facebook.com/v21.0`
Authentication: Bearer Token (OAuth 2.0 Long-Lived)
Rate Limits: ~200 write calls/hour per ad account

### Campaign Data Models [Source: docs/architecture.md#Data Models]

**CampaignConfig fields:**
- `type`: 'sales' | 'leads'
- `name`: string (nome do anúncio)
- `dailyBudget`: number (em centavos para Meta API)
- `adText`: `{ headline, primaryText, description, callToAction }`
- `pageId`, `instagramAccountId`, `adAccountId`
- `websiteUrl` (sales), `landingPageUrl` (leads)

**CampaignResult fields:**
- `campaignId`, `campaignName`, `adSetId`, `adId`
- `type`, `dailyBudget`, `status`, `creativeFormat`
- `adsManagerUrl`, `createdAt`

### Sales Campaign Strategy [Source: docs/architecture.md#Campaign Strategies]

- **Campaign**: `objective: OUTCOME_SALES`, `special_ad_categories: []`
- **Ad Set**: `optimization_goal: OFFSITE_CONVERSIONS`, `billing_event: IMPRESSIONS`, `promoted_object: { pixel_id, custom_event_type: PURCHASE }`, Advantage+ audience, daily_budget in centavos
- **Ad**: `object_story_spec` with page_id, link_data (image_hash/video_id, headline, body, description, call_to_action, link)

### Naming Convention [Source: docs/architecture.md#Naming Service]

Pattern: `PPT_[TYPE]_[EVENT]_[DD-MM-AA]_[NAME]`
- Sales: `PPT_VENDAS_COMPRA_09-03-26_BlackFriday`
- Leads: `PPT_LEADS_LP_09-03-26_Webinar`

### Rollback Strategy [Source: docs/architecture.md#Error Handling]

Compensating transactions on failure:
- Failed at createAdSet → delete campaign
- Failed at createAd → delete adSet + campaign
- Failed at activate → delete ad + adSet + campaign
- Failed rollback → log IDs for manual cleanup
