## Story

**As a** gestor de tráfego operando o squad `traffic-google`,
**I want** um comando `google-ads keyword-research` que consulta a API `KeywordPlanIdeaService.GenerateKeywordIdeas` e devolve volume médio mensal de buscas, concorrência, faixa de CPC e ideias relacionadas para palavras-semente,
**so that** eu possa validar **demanda de busca** e descobrir termos novos **antes** de criar campanhas Search — hoje isso só é possível abrindo o Planejador de Palavras-chave manualmente no Google Ads UI.

## Context

Primeira story do **Epic 7 — Google Ads Keyword Research**. Fonte da story: `docs/stories/epics/epic-7-google-ads-keyword-research/SPEC-keyword-research.md` (escrita pelo Performance Analyst do squad `traffic-google`).

**Pipeline dos épicos anteriores:**
- **Epic 5 (Done)** — CLI que **lê** performance (accounts, report nos 5 níveis incluindo `report --level keyword` via `keyword_view`)
- **Epic 6 (Done)** — CLI que **muta** (create/update/pause campanhas, ad_groups, keywords)
- **Epic 7 (esta)** — CLI que **pesquisa demanda** (keyword research pré-campanha)

**Diferença crítica vs `report --level keyword`:**
`report --level keyword` lê métricas de **keywords já ativas na conta** (via `keyword_view`). Esta story descobre **keywords novas + volume de busca do Google** (via `KeywordPlanIdeaService`) — palavras que ainda não estão em nenhuma campanha. São APIs e propósitos diferentes.

**Natureza read-only:** keyword research **não muta nada** na conta — é uma consulta. Não precisa de veto conditions de gasto, double-confirm, nem audit log de mutação. Diferente de todo o Epic 6.

**Conta usada na chamada:** a API exige um `customer_id` autenticado para rodar, mas os dados de volume são do Google (não da conta) — filtrados por geo + idioma. Qualquer conta acessível serve.

**Demanda real que originou a story:** pesquisa para o cliente **Bento Ghostwriting** (customer-id `4507487307`), nicho "escrever livro com IA", BR + pt-BR, 16 seeds (ver SPEC seção 7).

**O que NÃO faz parte desta story:**
- Criar KeywordPlan persistido na conta (a story usa GenerateKeywordIdeas, que é stateless)
- Forecast de campanha (impressões/cliques projetados — KeywordPlanService.GenerateForecastMetrics — fica para 7.2 futura se houver demanda)
- Salvar resultado direto em relatório formatado do Performance Analyst (integração com templates — pós-MVP)
- Sugestão de negative keywords
- Bulk via CSV de entrada (só `--seeds` inline + `--seeds-file` simples)

## Acceptance Criteria

1. Novo comando top-level `google-ads keyword-research` registrado no CLI (junto de `report`, `accounts`, etc).
2. O comando aceita as flags:
   - `--seeds <text>` (obrigatório, salvo se `--seeds-file` informado) — palavras separadas por vírgula
   - `--seeds-file <path>` (opcional) — arquivo texto, uma seed por linha (alternativa a `--seeds`)
   - `--geo <code>` (opcional, default `BR`) — aceita código (`BR`, `US`, `PT`) ou ID numérico cru do geo target constant
   - `--lang <code>` (opcional, default `pt`) — aceita código (`pt`, `en`) ou ID numérico cru do language constant
   - `--customer-id <id>` (opcional — usa default config)
   - `--login-customer-id <id>` (opcional — para contas sob MCC)
   - `--network <SEARCH|SEARCH_AND_PARTNERS>` (opcional, default `SEARCH`)
   - `--format <table|json>` (opcional, default `table`)
   - `--limit <n>` (opcional — corta as N ideias com mais volume; default sem corte)
3. A chamada usa `KeywordPlanIdeaService.GenerateKeywordIdeas` com: `customer_id`, `language` (resource `languageConstants/{id}`), `geo_target_constants` (`["geoTargetConstants/{id}"]`), `keyword_plan_network`, e `keyword_seed.keywords` = lista de seeds.
4. Cada linha de resultado contém:
   - `keyword` (texto)
   - `avg_monthly_searches` (volume médio mensal)
   - `competition` (LOW / MEDIUM / HIGH)
   - `competition_index` (0-100)
   - `low_top_of_page_bid` (R$ — micros divididos por 1.000.000)
   - `high_top_of_page_bid` (R$ — micros divididos por 1.000.000)
5. Resultado ordenado por `avg_monthly_searches` decrescente por padrão.
6. `--format json` retorna JSON estruturado (array de objetos) consumível por relatório do Performance Analyst; `--format table` imprime tabela legível em PT-BR com valores em R$.
7. **Validação client-side:**
   - Pelo menos 1 seed (de `--seeds` ou `--seeds-file`); senão exit 1 com mensagem PT-BR
   - Máx. 20 seeds; senão exit 1 indicando o limite
   - Geo/lang desconhecido (não no mapa e não numérico) → exit 1 com mensagem listando os códigos suportados
8. **Tratamento de erro da API (R2):** se a API retornar erro de permissão/autorização para Keyword Planner, exibir mensagem PT-BR clara e acionável (não stack trace cru), ex.:
   ```
   ❌ Não foi possível consultar o Planejador de Palavras-chave.
      Possíveis causas: developer token sem acesso a Keyword Planner, ou conta sem permissão.
      Detalhe da API: {mensagem original resumida}
   ```
9. **Boundary rule respeitada:** toda chamada ao SDK passa por um módulo novo `src/google-ads-api/keyword-ideas.ts`; nenhuma importação de `google-ads-api` fora de `src/google-ads-api/`.
10. A API quase sempre devolve **ideias relacionadas** além das seeds — todas devem ser incluídas no resultado (não filtrar só pelas seeds originais).
11. Testes unitários (≥80% cobertura nos arquivos novos):
    - `parseKeywordIdeasResponse(raw): KeywordIdea[]` (puro) — mapeia o shape do SDK para o nosso modelo, incluindo conversão de micros
    - `resolveGeoConstant(code): string` e `resolveLanguageConstant(code): string` (puros) — mapa + fallback numérico
    - `validateSeeds(seeds): {valid, error?}` (puro)
    - `formatKeywordIdeasTable(ideas, currency): string` (puro)
12. Smoke real-time (read-only — não muta nada):
    1. `google-ads keyword-research --seeds "marketing digital, agência de marketing" --geo BR --lang pt --customer-id 5562216599 --login-customer-id 1528041123 --format table` → tabela com volume/concorrência/CPC
    2. Mesmo comando com `--format json` → JSON válido
    3. `google-ads keyword-research --seeds "x"` com geo inválido (`--geo XX`) → erro PT-BR claro
    4. `--seeds ""` (vazio) → exit 1 com mensagem de seed obrigatória
    5. Rodar as 16 seeds reais da Bento Ghostwriting (SPEC seção 7) contra `--customer-id 4507487307` (com `--login-customer-id` se a conta exigir) → capturar JSON de saída para o Performance Analyst consolidar
