## Story

**As a** gestor de tráfego,
**I want** que o sistema leia e valide meus criativos da pasta configurada,
**so that** eu tenha certeza de que os arquivos estão corretos antes de subir a campanha.

## Acceptance Criteria

1. Sistema lê arquivos da pasta `~/Downloads/criativos-meta/` (configurável via `config.yaml`)
2. Identifica tipo de criativo automaticamente: imagem (JPG, PNG, WEBP), vídeo (MP4, MOV) ou múltiplos arquivos para carrossel
3. Valida dimensões mínimas conforme specs da Meta (1080x1080 para feed, 1080x1920 para stories)
4. Valida tamanho máximo: imagens até 30MB, vídeos até 4GB
5. Para carrossel: detecta quando há 2-10 imagens na pasta e sugere criação como carrossel
6. Exibe relatório de validação no terminal: arquivos encontrados, tipo detectado, status (válido/inválido) com motivo
7. Retorna erro claro em português se pasta vazia ou sem arquivos válidos
8. Testes unitários para cada tipo de validação

## Dev Notes

### Creative Module Architecture [Source: docs/architecture.md#Components]

The Creative Module (`src/creative/`) reads files from the creatives folder, detects type (image/video/carousel), validates against Meta specs, and prepares for upload.

Key interfaces from architecture:
- `scanCreatives(path: string): Promise<CreativeAsset[]>`
- `validateAsset(asset: CreativeAsset): ValidationResult`
- `buildBundle(assets: CreativeAsset[]): CreativeBundle`

Source tree:
```
src/creative/
├── scanner.ts              # Reads and detects files from folder
├── validator.ts            # Validates specs (dimensions, size, format)
└── bundle-builder.ts       # Builds CreativeBundle (single/carousel)
```

### Data Models [Source: docs/architecture.md#Data Models]

**CreativeAsset** — A creative file read from the local folder with validated metadata:
- `filePath`: string — Absolute file path
- `fileName`: string — File name
- `type`: 'image' | 'video' — Detected type
- `mimeType`: string — MIME type (e.g., image/jpeg, video/mp4)
- `width`: number — Width in pixels
- `height`: number — Height in pixels
- `fileSize`: number — Size in bytes
- `duration`: number | null — Duration in seconds (video only)
- `isValid`: boolean — Validation result
- `validationErrors`: string[] — Validation errors (if any)

**CreativeBundle** — Groups campaign creatives and defines ad format:
- `format`: 'single_image' | 'single_video' | 'carousel' — Detected format
- `assets`: CreativeAsset[] — Creative list (1 for single, 2-10 for carousel)
- `uploadedIds`: Map<string, string> — Map filePath → hash/ID after Meta upload

### Technology Stack [Source: docs/architecture.md#Tech Stack]

| Library | Version | Purpose |
|---------|---------|---------|
| sharp | 0.33.x | Image dimension reading — validates resolution without loading full image |
| fluent-ffmpeg | 2.x | Video metadata reading via ffprobe |
| ffprobe-static | 3.x | Bundled ffprobe binary — no system install needed |

### Code Review — Análise Manual

**Qualidade do código: Alta**

1. **Arquitetura:** Pipeline limpo scanner → validator → bundle-builder. Separação de responsabilidades clara, cada módulo com 1 propósito.

2. **Tipos:** `CreativeAsset` e `CreativeBundle` seguem fielmente os data models da arquitetura. MIME/extension maps são `as const` para type-safety.

3. **Error handling:** `CreativeError` estende `AppError` consistentemente. `probeVideo` wrapa callback do ffprobe em Promise. CLI catch diferencia `CreativeError` de erros inesperados.

4. **Testes:** Mocking strategy é sólida — mock de `sharp`, `fluent-ffmpeg`, `fs/promises` evita dependência de arquivos reais. `makeDirent()` helper é reutilizável. `makeAsset()` factory pattern nos testes de validator/bundle-builder.

### Observações (Severidade LOW — não bloqueantes)

1. **`resolvePath` com `~`** (`creatives.ts:18-19`): `inputPath.slice(2)` assume formato `~/path`. Se input for apenas `~` sem `/`, `slice(2)` retorna string vazia, o que resolve para homedir — comportamento correto. Se input for `~user/path` (Unix-style), seria incorreto, mas irrelevante para macOS single-user CLI.

2. **`fluent-ffmpeg` deprecated:** npm mostra deprecation warning. Funcional para ffprobe. Para stories futuras (Story 2.2 upload com progresso), pode ser necessário avaliar alternativa se surgem bugs.

3. **`validateAsset` muta o objeto:** O input `asset` é modificado diretamente (`asset.isValid = ...`). Funcional e documentado, mas um futuro refactor poderia retornar novo objeto para imutabilidade. Não é problema para o fluxo atual.

4. **Bundle builder com mix images+video:** Decisão documentada de priorizar vídeo. Adequado para MVP, mas pode gerar surpresa se usuário quer carousel de imagens + 1 vídeo separado. Considerar warning no futuro.
