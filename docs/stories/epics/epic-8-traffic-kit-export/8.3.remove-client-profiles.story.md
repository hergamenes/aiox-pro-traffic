## Story

**As a** gestor de tráfego que usa os squads em múltiplos projetos de cliente,
**I want** que nenhum dado de cliente real exista dentro dos arquivos dos squads,
**so that** instalar o Traffic Kit em qualquer projeto seja seguro por construção — sem risco de vazar dados de um cliente para outro.

## Context

Terceira story do **Epic 8 — Traffic Kit: Export dos Squads de Tráfego**. Depende de **Story 8.1 concluída** (CLIs via PATH) e **Story 8.2 concluída** (estrutura `traffic-shared/` estabilizada, incluindo `_TEMPLATE.md` já em `traffic-shared/data/client-profiles/`).

Hoje os squads carregam perfis de cliente reais embutidos: `squads/traffic-meta/data/client-profiles/medical-spin.md` e `squads/traffic-google/data/client-profiles/medical-spin.md`. Isso viola o princípio de isolamento de dados (constraint INEGOCIÁVEL do epic): dados de um cliente não podem residir em artefatos que serão copiados para projetos de outros clientes.

A convenção de perfis por projeto já está parcialmente em uso no squad `traffic-google` (`reports/{cliente-plataforma-id}/client-profile.md`). Esta story formaliza e documenta essa convenção, remove os perfis reais dos squads e atualiza os agentes/tasks que os liam.

**Importante: antes de deletar, verificar se o conteúdo precisa ser preservado.** O perfil `medical-spin.md` pode conter dados relevantes que devem ser movidos para o path correto por projeto (`reports/medical-spin-meta/client-profile.md` e `reports/medical-spin-google/client-profile.md`) — mover, não perder.

**O que NÃO faz parte desta story:**
- Criar perfis de cliente para outros clientes (feito por projeto, sob demanda)
- Criar o installer (8.4)
- Migrar automaticamente todos os perfis existentes nos projetos já instalados

## Acceptance Criteria

1. Removidos `squads/traffic-meta/data/client-profiles/medical-spin.md` e `squads/traffic-google/data/client-profiles/medical-spin.md` — e quaisquer outros arquivos de perfil de cliente real encontrados em `squads/` (grep por nomes de clientes).
2. O conteúdo dos perfis removidos foi preservado: movido para `reports/medical-spin-meta/client-profile.md` e `reports/medical-spin-google/client-profile.md` (ou path equivalente confirmado na implementação), antes da deleção.
3. Mantido apenas `data/client-profiles/_TEMPLATE.md` como referência — em `squads/traffic-shared/data/client-profiles/_TEMPLATE.md` (conforme estrutura criada pela 8.2).
4. Definida e documentada a convenção de onde perfis de cliente vivem por projeto: `reports/{cliente}/client-profile.md` (com `{cliente}` sendo o identificador do cliente — ex.: `medical-spin-meta`, `medical-spin-google`, `verbo-feminino-meta`).
5. Referências em agentes e tasks que liam perfis embutidos (ex.: `squads/traffic-meta/data/client-profiles/medical-spin.md`) atualizadas para a convenção por projeto — com instrução ao agente de procurar `reports/{cliente}/client-profile.md` e usar `_TEMPLATE.md` como fallback se o perfil não existir.
6. Validação final: grep exaustivo por nomes de clientes reais conhecidos (`medical-spin`, `Medical Spin`, `SOL`, `Verbo Feminino`, `verbo-feminino`, `Bento`, `bento`) dentro de `squads/` retorna zero ocorrências em arquivos de dados/perfil — isolamento garantido por construção.

## Dev Notes

**Contexto crítico para o @dev:**

- **Dependências obrigatórias:** Story 8.1 Done (CLI via PATH) e Story 8.2 Done (incluindo `_TEMPLATE.md` já movido para `squads/traffic-shared/data/client-profiles/`). Se a 8.2 não estiver concluída, o `_TEMPLATE.md` ainda estará em cada squad individualmente
- **Constraint INEGOCIÁVEL (Art. 9 do epic):** isolamento de clientes é inegociável. Nenhum dado de cliente real pode residir dentro de `squads/`. Esta constraint supera qualquer outra consideração de conveniência
- **Clientes reais conhecidos neste repo:**
  - Medical Spin (SOL) — equipamentos de imagem médica B2B; Meta account `1363484047451149`, Google account `2031520209`
  - Verbo Feminino — moda fitness; Meta account `884611416502961`
  - Bento Ghostwriting — Google account `4507487307`
  - Revenda de carros — Meta account `3452620158369704`
  - Grupo Prestarh — Google account `9631900143`
- **Convention de path por projeto:** `reports/{cliente-plataforma-id}/client-profile.md` — o sufixo `-meta` ou `-google` é importante quando o mesmo cliente (como Medical Spin/SOL) usa ambas as plataformas, pois os dados de conta são diferentes
- **Referências aceitáveis vs dados reais:** menção de nomes de cliente como exemplos em comentários do `_TEMPLATE.md` ou como exemplo de ID em README são aceitáveis (contexto documental); dados de conta reais (IDs, credenciais, orçamentos, histórico de campanha) são o que deve ser removido
- **Risco E-R3 (do epic):** vazamento residual de dados. O grep exaustivo do Task 2 e a validação do Task 6 são os gates. Incluir variações de nome (maiúsculas, hífens, sem acento)
- **reports/ já existe:** o diretório `reports/` já existe no repo (usado em sessões anteriores). Confirmar presença antes de criar subpastas
- **Conteúdo típico de client-profile.md:** conta de anúncios (ID, nome), objetivo principal das campanhas, público-alvo, CPA meta, observações estratégicas. Confirmar o conteúdo real dos arquivos antes de mover
