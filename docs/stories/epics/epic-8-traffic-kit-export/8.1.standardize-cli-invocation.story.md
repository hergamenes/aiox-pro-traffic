## Story

**As a** gestor de tráfego usando o squad `traffic-meta`,
**I want** que todos os arquivos do squad invoquem o CLI como `meta-ads ...` (via PATH global),
**so that** os agentes, tasks e workflows funcionem corretamente fora deste repositório — em qualquer pasta de projeto onde o kit for instalado.

## Context

Primeira story do **Epic 8 — Traffic Kit: Export dos Squads de Tráfego**.

Hoje o squad `traffic-meta` invoca o CLI por path relativo ao repositório (`node packages/meta-ads-agent/dist/bin/meta-ads.js ...`). Isso torna o squad não-portável: fora deste repo o path não existe e todos os comandos falham. A solução é simples — substituir toda referência de invocação por `meta-ads ...` (o binário global instalado via `npm install -g`).

O squad `traffic-google` já usa `google-ads` direto (sem path relativo), mas precisa ser auditado para confirmar que não há resíduos de path relativo.

Esta story é a **base de portabilidade do epic**. As stories 8.2, 8.3 e 8.4 dependem dela.

**O que NÃO faz parte desta story:**
- Criar o script de instalação global (coberto pela 8.4)
- Extrair conteúdo comum para `traffic-shared/` (8.2)
- Remover perfis de cliente (8.3)
- Instalar os CLIs em máquinas de destino (8.4)

## Acceptance Criteria

1. Toda invocação de CLI no squad `traffic-meta` (agentes, tasks, workflows, data, checklists, README, user-guide) usa `meta-ads ...` via PATH — zero ocorrências de `node packages/meta-ads-agent/dist/bin/meta-ads.js` ou `cd packages/meta-ads-agent` como mecanismo de invocação.
2. Squad `traffic-google` auditado e confirmado consistente: usa `google-ads` via PATH em todos os seus arquivos `.md`; qualquer desvio remanescente corrigido.
3. Documentado em nota (Dev Notes ou README do squad, onde mais adequado) o procedimento de instalação global dos 2 CLIs a partir de `packages/`: `npm install && npm run build` em cada pacote seguido de `npm install -g .` (ou equivalente `npm link`).
4. Após instalação global, `meta-ads --version` e `google-ads --version` (ou equivalente — confirmar flag de versão disponível no CLI) retornam resposta de qualquer diretório.
5. Nenhuma referência de path relativo do repositório permanece nos arquivos dos squads como mecanismo de invocação (referências documentais sobre onde o código-fonte vive — ex.: "o CLI está em `packages/meta-ads-agent/`" — são aceitáveis se claramente contexto documental, não invocação).

## Dev Notes

**Contexto crítico para o @dev:**

- **Path atual a eliminar (traffic-meta):** `node packages/meta-ads-agent/dist/bin/meta-ads.js` — este é o padrão frágil a substituir por `meta-ads`
- **Invocação correta (após instalação global):** `meta-ads <comando> [flags]` — exatamente como `google-ads` já funciona no squad traffic-google
- **Escopo de arquivos no traffic-meta:** `squads/traffic-meta/agents/*.md`, `squads/traffic-meta/tasks/*.md`, `squads/traffic-meta/workflows/*.md`, `squads/traffic-meta/checklists/*.md`, `squads/traffic-meta/data/*.md`, `squads/traffic-meta/README.md`, `squads/traffic-meta/user-guide.md` (confirmar existência de cada um)
- **Escopo de arquivos no traffic-google:** apenas auditoria; espera-se zero ocorrências de path relativo, mas confirmar
- **Distinguir invocação de documentação:** frases como "o CLI está em `packages/meta-ads-agent/`" são documentação legítima e NÃO devem ser removidas. Apenas linhas que efetivamente invocam o CLI com path relativo devem ser corrigidas
- **Flags e argumentos:** ao substituir a invocação, preservar todas as flags (`--account-id`, `--format`, etc.) exatamente como estão — apenas o prefixo `node packages/.../meta-ads.js` vira `meta-ads`
- **Verificação de versão:** confirmar via `packages/meta-ads-agent/package.json` se existe script `version` ou se o CLI aceita `--version`; se não existir, documentar o workaround (ex.: `meta-ads --help` como verificação de saúde)
- **Risco E-R1 (do epic):** `npm install -g` pode ter problemas de permissão em algumas máquinas (nvm, sudo). A nota de instalação deve mencionar isso e referenciar o README-TRAFFIC-KIT.md que a 8.4 criará com troubleshooting completo
