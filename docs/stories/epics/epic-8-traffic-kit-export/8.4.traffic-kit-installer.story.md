## Story

**As a** gestor de tráfego que inicia um novo projeto de cliente,
**I want** um único comando que copia os squads, CLIs e configurações para qualquer pasta de projeto,
**so that** eu possa ter o Traffic Kit operacional num projeto novo em minutos — sem copiar arquivos manualmente, sem ajustar paths e sem risco de esquecermos algo.

## Context

Quarta e última story do **Epic 8 — Traffic Kit: Export dos Squads de Tráfego**. Depende de **Stories 8.1, 8.2 e 8.3 todas concluídas**: CLIs padronizados via PATH (8.1), `traffic-shared/` como fonte única (8.2), squads livres de dados de cliente (8.3).

Esta story entrega o empacotamento final: o script `install-traffic-kit.sh` que reproduz o ambiente em qualquer projeto, o `README-TRAFFIC-KIT.md` que documenta todo o ciclo de vida do kit, e o bundle de branding Solaro (se os assets existirem no repo).

**Princípio KISS:** installer é shell script local. Sem npm publish, sem framework de instalação, sem CI/CD. Um comando — funciona.

**Constraint crítico (isolamento):** o installer NUNCA copia `reports/` nem `data/client-profiles/` com dados reais. Ele copia os squads limpos (já garantido pelas stories 8.1-8.3).

**O que NÃO faz parte desta story:**
- Instalar/configurar o MCP Facebook (é conector da conta claude.ai — só documentar no README)
- Novas features dos squads ou CLIs
- CI/CD para o installer
- Migração automática de perfis de cliente existentes
- Publicar o kit como pacote npm

## Acceptance Criteria

1. `scripts/install-traffic-kit.sh <destino>` copia `squads/traffic-shared/`, `squads/traffic-meta/`, `squads/traffic-google/`, `.claude/commands/trafficMeta/` e `.claude/commands/trafficGoogle/` para o projeto de destino — mantendo a estrutura de diretórios.
2. O script verifica se `meta-ads` e `google-ads` estão disponíveis no PATH do sistema; se ausentes, executa build (`npm install && npm run build`) e `npm install -g .` para cada CLI a partir de `packages/meta-ads-agent/` e `packages/google-ads-agent/` respectivamente.
3. O script cria o diretório `reports/` no projeto de destino (se não existir).
4. O script faz **merge** das allow rules de LEITURA no `.claude/settings.local.json` do destino: `meta-ads` (subcomandos de leitura: `report`, `accounts`, `auth status`) e `google-ads` (idem) — adicionando apenas as regras ausentes, **nunca sobrescrevendo** regras existentes. Se o arquivo não existir, cria com as allow rules mínimas.
5. O script copia os assets de branding Solaro (logos PNG, HTML modelo) para o destino, **se** os assets existirem no repo (`reports/solaro-*` ou path identificado na implementação). A ausência de branding NÃO bloqueia a instalação.
6. `README-TRAFFIC-KIT.md` na raiz do repo documenta: (a) o que é o Traffic Kit e seus componentes, (b) instalação em projeto novo (1 comando), (c) setup em máquina nova (auth via Keychain para Meta e Google, com comandos exatos), (d) o conector MCP `claude_ai_Facebook` da conta claude.ai — o que é, onde fica, que não há nada a instalar; apenas informar o usuário, (e) como criar e usar `client-profile.md` por projeto, (f) troubleshooting (PATH/npm/nvm, permissões).
7. O installer é **idempotente**: rodar 2x no mesmo destino não duplica squads, não sobrescreve allow rules já presentes, não quebra o projeto.
8. O installer NUNCA copia `reports/` com conteúdo (a pasta `reports/` é criada vazia) nem qualquer `client-profiles/*.md` que não seja `_TEMPLATE.md`.

## Dev Notes

**Contexto crítico para o @dev:**

- **Dependências obrigatórias:** Stories 8.1 + 8.2 + 8.3 todas em Done antes de executar esta story. O installer empacota o resultado dessas 3 stories — qualquer desvio nas fontes chega ao destino
- **Shell: bash, macOS/zsh-compatível.** O script deve ter shebang `#!/usr/bin/env bash` e ser executável (`chmod +x`). Testar no macOS (o usuário usa Apple Silicon)
- **Merge de allow rules — abordagem recomendada:**
  - Se `jq` disponível: `jq '.allow |= (. + $new_rules | unique)'` — idiomático e seguro
  - Se não: fallback via `node -e` inline com `JSON.parse` / `JSON.stringify` e lógica de merge manual
  - Em nenhum caso usar `echo > arquivo` (sobrescreve). Sempre ler, modificar na memória, escrever de volta
  - Allow rules de leitura a adicionar (formato a confirmar observando o `.claude/settings.local.json` atual do repo de origem):
    ```json
    {"command": "meta-ads accounts"},
    {"command": "meta-ads report"},
    {"command": "meta-ads auth status"},
    {"command": "google-ads accounts"},
    {"command": "google-ads report"},
    {"command": "google-ads auth status"}
    ```
  - Confirmar o schema exato do `settings.local.json` lendo o arquivo do próprio repo antes de implementar
- **Idempotência:** o principal risco é duplicar allow rules ou sobrescrever squads. Usar `cp -n` para arquivos e verificação de existência antes de adicionar regras resolve a maioria dos casos
- **Branding Solaro:** se localizado no Task 1, copiar para `$DESTINO/reports/branding-solaro/` (ou path equivalente já usado no repo). Se não localizado, o README documenta onde obter os assets manualmente
- **NÃO copiar:** `reports/` com conteúdo, qualquer `client-profiles/{cliente}.md` que não seja `_TEMPLATE.md`, `node_modules`, `.env`, `packages/` (o installer usa packages/ como fonte para build/install-g, mas não os copia para o destino)
- **Risco E-R4 (do epic):** installer sobrescreve `settings.local.json`. O merge via jq/node com verificação antes de append mitiga completamente. Fazer backup do arquivo existente antes de tocar: `cp settings.local.json settings.local.json.bak` é boa prática e deve ser implementado
- **Risco E-R1 (do epic):** `npm install -g` com problemas de permissão (nvm, sudo no macOS). O script deve: (a) verificar `command -v meta-ads` antes de tentar instalar, (b) se a instalação falhar, emitir mensagem clara com troubleshooting, (c) não abortar a instalação completa por causa de CLI — continuar e avisar
- **Verificar estrutura de comandos antes de copiar:** confirmar que `.claude/commands/trafficMeta/` e `.claude/commands/trafficGoogle/` existem no repo (devem existir como shims de ativação dos agentes)
- **README-TRAFFIC-KIT.md:** criar na raiz do repo (`/Users/hergamenessouza/aiox-pro-traffic/README-TRAFFIC-KIT.md`). Linguagem: português do Brasil, tom direto, instruções passo a passo numeradas (o usuário é iniciante em programação)
