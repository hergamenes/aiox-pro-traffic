## Story

**As a** gestor de tráfego,
**I want** consultar métricas de performance das minhas campanhas em tempo real via CLI,
**so that** eu possa analisar resultados sem precisar abrir o Gerenciador de Anúncios.

## Acceptance Criteria

1. Comando `meta-ads report {ad-account-id}` retorna relatório de performance com as 22 métricas definidas
2. Suporte a filtro de período: `--period=7d|14d|30d` e `--from=YYYY-MM-DD --to=YYYY-MM-DD`
3. Suporte a nível de detalhamento: `--level=account|campaign|adset|ad` (padrão: `campaign`)
4. Função `getInsights()` adicionada ao adapter (`src/meta-api/adapter.ts`) consultando `GET /act_{id}/insights`
5. Campos API consultados: `spend,impressions,cpm,frequency,actions,cost_per_action_type,website_ctr,purchase_roas`
6. Métricas extraídas do array `actions` por `action_type`: `link_click`, `landing_page_view`, `offsite_conversion.fb_pixel_initiate_checkout`, `offsite_conversion.fb_pixel_purchase`, `offsite_conversion.fb_pixel_lead`
7. 3 métricas calculadas localmente: taxa de visualizações por cliques no link, taxa de compras por cliques no link, taxa de compras por visualizações da página de destino
8. Output formatado em tabela legível no terminal com valores monetários em R$ e percentuais com 2 casas decimais
9. Suporte a `--format=table|json` (padrão: `table`) para integração com outros comandos
10. Mensagens de erro em português para falhas de consulta
11. Suporte a filtro por campanha: `--campaign-id=ID` filtra por campaign ID exato
12. Suporte a filtro por tag de funil no nome: `--tag=TAG` filtra campanhas cujo nome contém a tag (case-insensitive, match parcial). Ex: `--tag=VENDAS` retorna todas as campanhas com "VENDAS" no nome
13. Filtros `--campaign-id` e `--tag` podem ser combinados com `--level` (quando filtrado por campanha, level padrão muda para `adset` para mostrar detalhamento)
14. Testes unitários cobrindo parsing de insights, cálculos de taxas, formatação e filtros de campanha

## Technical Notes

- **Adapter pattern:** Segue o mesmo padrão de `listAdAccounts()` e `createCampaign()` já existentes
- **Meta API version:** v21.0 (constante `API_VERSION` no adapter)
- **Pagination:** API de insights retorna paginado — seguir `paging.next` até acabar
- **Token:** Longa duração, expira 11/05/2026 — já configurado
- **Insights delay:** Dados da Meta API podem ter delay de até 30 minutos. Documentar isso para o usuário
- **Rate limiting:** A API de insights tem rate limit mais restrito — usar `withRetry()` existente
- **Budget:** Orçamento não vem do endpoint `/insights` — vem de `GET /act_{id}/adsets?fields=daily_budget,lifetime_budget`
- **Nomenclatura de campanhas:** Campanhas seguem padrão `PPT_[TIPO]_[EVENTO]_[DD-MM-AA]_[NOME]`. Tags de funil são extraídas do nome (ex: `VENDAS`, `LEADS`, `COMPRA`). O filtro `--tag` faz match parcial case-insensitive no `campaign_name`
- **Filtering API:** A Meta API suporta `filtering` param para filtrar por `campaign.id` server-side, mas NÃO suporta filtro por nome — por isso o filtro `--tag` é client-side (fetch all, then filter)
- **Sem novas dependências** — usa apenas pacotes já instalados (commander, pino, zod)
