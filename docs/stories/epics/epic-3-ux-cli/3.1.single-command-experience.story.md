## Story

**As a** gestor de tráfego,
**I want** criar campanhas com um único comando natural,
**so that** eu não precise lembrar subcomandos e flags separados.

## Acceptance Criteria

1. Comando unificado `meta-ads up` aceita parâmetros inline: `meta-ads up sales "BlackFriday" --budget 50`
2. Parâmetros opcionais: `--page`, `--budget`, `--url` (para leads)
3. Quando parâmetros obrigatórios faltam (textos do anúncio, orçamento), sistema faz prompts interativos com `@inquirer/prompts`
4. Suporte a atalhos: `meta-ads up sales` (prompta tudo), `meta-ads up leads --url https://...` (prompta o resto)
5. Detecção automática de tipo de criativo na pasta sem precisar informar
6. Fluxo completo executado em sequência: validar criativos → upload → criar campanha → ativar → exibir resumo
7. Testes cobrindo cenários: todos os params inline, nenhum param (full prompt), params parciais

### Key Implementation Notes

- **`up` command is NEW** — it does NOT replace `create sales` / `create leads`. Both exist in parallel.
- **`up` command reuses** ALL existing infrastructure (orchestrator, strategies, page-resolver, creative pipeline)
- **The difference** is that `up` provides a unified entry point with smart prompting for missing params
- **DO NOT modify the orchestrator** — all logic lives in the CLI layer (`up.ts` and `prompts.ts`)
- **DO NOT modify strategies** — they already handle both campaign types
- **DO NOT modify `create.ts`** — the existing `create sales` / `create leads` commands remain unchanged
- **Budget conversion:** `dailyBudget` in `CampaignConfig` is in cents. The `up` command receives R$ from user and converts: `Math.round(parseFloat(budget) * 100)`
- **Creative auto-detection:** `buildBundle()` already detects format based on number and type of validated assets. No extra logic needed.
- **`--url` flag** serves dual purpose: `websiteUrl` for sales, `landingPageUrl` for leads. Determined by campaign type.
