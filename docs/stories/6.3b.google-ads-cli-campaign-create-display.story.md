## Story

**As a** gestor de tráfego operando o squad `traffic-google`,
**I want** o comando `google-ads create campaign-display` que cria novas campanhas do tipo **Display** via CLI (Campaign + CampaignBudget atômicos, em status PAUSED por default),
**so that** eu possa preparar campanhas de display/remarketing rapidamente para múltiplos clientes da MCC Solaro sem abrir o Google Ads UI — mantendo os mesmos veto conditions da 6.3a (PAUSED por default, MCC check, cap de session-budget) e respeitando a especificidade do canal Display (sem keywords, network apenas content).

## Risks

| ID | Risco | Probabilidade | Impacto | Mitigação |
|----|-------|--------------|---------|-----------|
| R1 | Campanha criada accidentalmente em ENABLED gera spend | Baixa | **Crítico financeiro** | Default `status: PAUSED` hardcoded; flag `--enable-now` exige double-confirm explícito (mesma regra da 6.3a) |
| R2 | `network_settings` incorreto (Search + Display mixed) gera entrega indevida | Média | Alto | Hardcode `target_google_search=false`, `target_search_network=false`, `target_content_network=true`; validar via GAQL pós-create |
| R3 | Bidding strategy inadequada para Display sem audience (MAXIMIZE_CONVERSIONS exige conversions configuradas) | Média | Médio | Warning explícito se conta não tem conversion actions ativas; sugere `MAXIMIZE_CLICKS` como fallback seguro |
| R4 | Budget alto excede session cap (mesma regra da 6.3a) | Média | Alto | Cap `--max-session-budget` (default R$ 100/dia) bloqueia criação até double-confirm |
| R5 | Operator confunde `create campaign-display` com `create campaign-search` (typo) | Baixa | Médio | Output do `--help` deixa explícito o `advertising_channel_type` que será aplicado; preview mostra "Tipo: DISPLAY" antes de confirmar |
| R6 | SDK rejeita combinação Display + bidding strategy não suportada (ex: TARGET_ROAS sem assets) | Baixa | Baixo | Lista de strategies válidas para Display documentada na lib local; CLI valida antes de chamar API |

## Acceptance Criteria

1. Novo subcomando `google-ads create campaign-display <name>` registrado no CLI sob o parent `create` (irmão de `campaign-search` da 6.3a)
2. Argumentos obrigatórios:
   - `<name>` (positional, primeira posição) — nome da campanha; usado também para `{name} Budget`
   - `--daily <amount>` — budget diário em currency da conta (parser reusa `parseMicros` da 6.1)
3. Argumentos opcionais:
   - `--bidding <strategy>` — default `maximize_conversions`; aceita `maximize_conversions | target_cpa | maximize_conversion_value | maximize_clicks`
   - `--target <value>` — obrigatório quando strategy é `target_cpa` (currency) ou `target_roas` (decimal)
   - `--start-date <YYYY-MM-DD>` — default hoje
   - `--customer-id <id>` (opcional — usa default)
   - `--login-customer-id <id>` (opcional — mesma flag da 6.1; necessária para acesso a sub-contas da MCC)
   - `--dry-run` (validate_only=true; não cria)
   - `--max-session-budget <amount>` (default 100; cap anti-runaway)
   - `--enable-now` (opt-in; default é PAUSED) — exige double-confirm
4. **Atomic create**: CLI chama `customer.mutateResources([...])` com **2 operações em UMA chamada**:
   - `campaign_budget` create (com `resource_name: customers/{cid}/campaignBudgets/-1` temp)
   - `campaign` create (referenciando `campaign_budget: customers/{cid}/campaignBudgets/-1`)
   - Se qualquer operação falha → rollback automático (API garante atomicidade)
5. **Display-specific defaults aplicados automaticamente:**
   - `advertising_channel_type: 'DISPLAY'`
   - `status: 'PAUSED'` (a menos que `--enable-now`)
   - `network_settings.target_content_network: true`
   - `network_settings.target_google_search: false`
   - `network_settings.target_search_network: false`
   - `network_settings.target_partner_search_network: false`
6. **Anti-runaway session cap** (Veto crítico):
   - Se `daily_budget > max_session_budget`: pausa, mostra delta, exige double-confirm com frase exata (`"sim, criar com R$ X/dia"`)
   - Cap default conservador (R$ 100/dia) — mesmo da 6.3a
7. **MCC check** (Veto crítico): se customer-id é MCC (manager account), exit 1 com mensagem PT-BR orientativa — campanhas só podem ser criadas em sub-contas (Story 5.4 já valida tree, esta story re-confirma explicitamente antes de mutar)
8. **Bidding strategy validation:**
   - Lista válida para Display: `maximize_conversions | target_cpa | maximize_conversion_value | maximize_clicks`
   - Se `target_cpa` ou `maximize_conversion_value` selecionada e conta não tem conversion actions ativas → warning explícito (não bloqueia, mas alerta sobre risco de não-entrega)
   - `target_roas` NÃO listada por exigir feed/assets (out of scope MVP)

### SDK signature — atomic mutateResources

```ts
import { GoogleAdsApi, resources, enums, MutateOperation } from 'google-ads-api';

const customer = client.Customer({ customer_id, refresh_token, login_customer_id });

const operations: MutateOperation<resources.ICampaignBudget | resources.ICampaign>[] = [
  {
    entity: 'campaign_budget',
    operation: 'create',
    resource: {
      resource_name: `customers/${customer_id}/campaignBudgets/-1`,
      name: `${campaignName} Budget`,
      amount_micros: dailyMicros,
      delivery_method: enums.BudgetDeliveryMethod.STANDARD,
      explicitly_shared: false,
    },
  },
  {
    entity: 'campaign',
    operation: 'create',
    resource: {
      name: campaignName,
      advertising_channel_type: enums.AdvertisingChannelType.DISPLAY,
      status: enums.CampaignStatus.PAUSED, // default; PAUSED a menos que --enable-now
      campaign_budget: `customers/${customer_id}/campaignBudgets/-1`,
      // Bidding (mutuamente exclusivo conforme strategy):
      maximize_conversions: {}, // ou target_cpa: { target_cpa_micros }, ou maximize_clicks: {}, etc.
      network_settings: {
        target_google_search: false,
        target_search_network: false,
        target_content_network: true,
        target_partner_search_network: false,
      },
      start_date: startDate, // YYYY-MM-DD
    },
  },
];

const result = await customer.mutateResources(operations, {
  validate_only: dryRun, // true para --dry-run
});

// result.results[0].resource_name = campaign_budget resource_name (definitivo)
// result.results[1].resource_name = campaign resource_name (definitivo)
```

**Pontos-chave do pattern atomic:**
- Temp `resource_name: '.../-1'` (negativo) sinaliza ao Google "este recurso ainda não existe, será criado nesta mesma chamada"
- A campanha referencia o budget via `campaign_budget: '.../-1'` mesmo antes do budget ter ID real — o Google resolve a referência atomicamente
- Se qualquer operação falha, **NADA é criado** — rollback automático pela API

### Diferenças Display vs Search (decisão arquitetural)

| Aspecto | Search (6.3a) | Display (6.3b) |
|---------|---------------|----------------|
| `advertising_channel_type` | `SEARCH` | `DISPLAY` |
| `network_settings.target_google_search` | `true` | `false` |
| `network_settings.target_search_network` | `true` (default) | `false` |
| `network_settings.target_content_network` | `true` (Display partners) | `true` (principal) |
| Bidding default | `maximize_clicks` ou `manual_cpc` | `maximize_conversions` |
| Bidding strategies válidas | Todas (incl. `manual_cpc`) | Subset (sem `manual_cpc` na MVP) |
| Keywords no AdGroup (6.4) | SIM (obrigatório) | NÃO (usa audiences/topics) |
| Ads no AdGroup (6.5) | RSA (Responsive Search Ads) | RDA (Responsive Display Ads) |
| Audience targeting | Opcional (broadening) | **Principal** mecanismo (POST-MVP, Story 6.4+) |

### Decisão: bidding default `MAXIMIZE_CONVERSIONS`

- **Por que não `manual_cpc`:** Display sem audience+conversion tracking + manual CPC é receita para spend sem retorno. Google deprecated essa configuração para campanhas Display novas em vários mercados.
- **Por que não `target_cpa`:** exige conversion actions ativas E histórico de conversões — para conta nova/MVP é provável que não tenha.
- **`maximize_conversions` como default:** mesmo sem histórico, Google aplica modelo genérico e a campanha em PAUSED não consome budget até operator decidir ativar.
- **Warning quando faltam conversion actions:** se a conta não tem `conversion_action` ativa, CLI emite warning explicando que `maximize_conversions` pode não entregar volume sem dados. Sugere `maximize_clicks` como fallback seguro para validação inicial.

### Decisão: status PAUSED por default

Mesma regra da 6.3a — herança direta. Display em PAUSED não impacta orçamento; operator decide quando ativar via Story 6.2.

### Decisão: audience/topic/placement targeting fora desta story

Esta story cria a campanha **sem targeting de audience**. Sem audience, a campanha Display em ENABLED entregaria broad (qualquer placement na Display Network) — alto risco de spend sem ROI. Por isso o lembrete explícito no preview (AC#9): a campanha precisa de Story 6.4 (Ad Group + audience targeting) antes de fazer sentido ativar.

### Veto Conditions (não fazer)

- ❌ Criar campanha em ENABLED sem `--enable-now` + double-confirm
- ❌ Hardcode `target_google_search=true` (transformaria em campanha mista, viola contract)
- ❌ Aceitar `target_roas` na MVP (exige feed/assets — fora do escopo)
- ❌ Pular MCC check (Story 5.4 valida, mas re-check aqui é defesa em profundidade)
- ❌ Importar `google-ads-api` (npm) fora de `src/google-ads-api/`
- ❌ Logar `refresh_token` ou OAuth secrets no mutation log
- ❌ Skip do log mesmo em dry-run (dry-run também gera entrada com `dryRun: true`)
