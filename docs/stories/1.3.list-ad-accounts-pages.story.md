## Acceptance Criteria

1. Comando `meta-ads accounts` lista todas as Ad Accounts acessíveis com ID, nome e status
2. Comando `meta-ads pages` lista todas as Páginas do Facebook com ID, nome e categoria
3. Comando `meta-ads pages` também mostra a conta do Instagram conectada (se houver)
4. Comando `meta-ads config set-default` permite definir Ad Account, Página do Facebook e perfil do Instagram padrão
5. Configurações padrão salvas em arquivo local (`~/.meta-ads/config.yaml`)
6. Todos os comandos validam autenticação antes de executar e orientam o usuário a rodar `meta-ads auth setup` se não autenticado
7. Output formatado em tabela legível no terminal

## Dev Notes

### Meta API Adapter Architecture [Source: docs/architecture.md#Components]

The Meta API Adapter (`src/meta-api/adapter.ts`) encapsulates all communication with the Meta Marketing API via the official SDK. It isolates the application from API/SDK changes.

Key interfaces from architecture:
- `listAdAccounts(): Promise<AdAccount[]>`
- `listPages(): Promise<Page[]>`
- `uploadImage(adAccountId, filePath): Promise<string>` (future — Story 2.2)
- `uploadVideo(adAccountId, filePath, onProgress): Promise<string>` (future — Story 2.2)

### Meta Marketing API Endpoints [Source: docs/architecture.md#External APIs]

| Method | Endpoint | Purpose |
|--------|----------|---------|
| `GET` | `/me/adaccounts` | List user's Ad Accounts |
| `GET` | `/me/accounts` | List Facebook Pages |
| `GET` | `/{page-id}?fields=instagram_business_account` | Get connected Instagram |

- **Base URL:** `https://graph.facebook.com/v21.0`
- **Authentication:** OAuth 2.0 Bearer Token (Long-Lived, 60 days)
- **Rate Limits:** ~200 calls/hour (write), ~6400 calls/hour (read)
- **SDK:** `facebook-nodejs-business-sdk@22` abstracts pagination, payload construction, error handling

### Config Repository Architecture [Source: docs/architecture.md#Components]

Config Repository (`src/config/config-repository.ts`) reads and writes settings from `~/.meta-ads/config.yaml`.

Config File Schema [Source: docs/architecture.md#Database Schema]:
```yaml
version: 1
defaults:
  adAccountId: "act_123456789"
  pageId: "987654321"
  instagramAccountId: "111222333"
creativesPath: "~/Downloads/criativos-meta/"
logPath: "~/.meta-ads/campaigns.log"
app:
  appId: "444555666"
  callbackPort: 3000
```

### Error Handling [Source: docs/architecture.md#Error Handling Strategy]

Error hierarchy already created in Story 1.2:
```
AppError (base)
├── AuthError       ← already exists
├── ValidationError ← already exists
├── MetaApiError    ← already exists (with metaErrorCode)
├── NetworkError    ← already exists
```

Meta Error Code translation map [Source: docs/architecture.md#Error Translation Map]:
| Meta Error Code | Portuguese Message | Suggested Action |
|----------------|-------------------|-----------------|
| 190 | Token de acesso inválido ou expirado | Execute: `meta-ads auth setup` |
| 100 | Parâmetro inválido: {param} | Verifique: {detalhe} |
| 4 | Limite de chamadas da API atingido | Aguarde alguns minutos |
| 10 | Permissão negada | Verifique permissões do Meta App |

### Coding Standards [Source: docs/architecture.md#Coding Standards]

- **ESM modules:** `"type": "module"` in package.json
- **Strict TypeScript:** `"strict": true` in tsconfig
- **Path aliases:** `@/*` → `src/*` (avoid `../../../` imports)
- **File naming:** kebab-case (`config-repository.ts`)
- **Max 200 lines per file**
- **Async/await everywhere** — never `.then()/.catch()`
- **Pino redact:** Always configure redact for sensitive fields
- **Never log tokens** — use pino.redact for accessToken, appSecret, headers.authorization
- **Meta SDK types are unreliable** — always type returns in MetaApiAdapter with our interfaces

### Testing [Source: docs/architecture.md#Test Strategy]

- **Framework:** vitest 3.x
- **Location:** `tests/unit/` mirrors `src/`, `tests/integration/` by flow
- **Naming:** `{module}.test.ts`
- **Pattern:** AAA (Arrange, Act, Assert)
- **Coverage target:** 80%+ overall
- **Mock keytar:** Native module, must be mocked in tests
- **Mock Meta SDK:** Use `vi.mock('facebook-nodejs-business-sdk')` for unit tests

### Previous Story Insights (Story 1.2)

- keytar@7 works on macOS Apple Silicon with Node.js 24.x
- vi.mock hoisting: Use inline factory in `vi.mock()` and import module AFTER mock declaration
- Auth module complete: `getAccessToken()`, `getAuthStatus()`, `saveToken()`, `isTokenExpiringSoon()` all available
- Error types complete: `AppError`, `AuthError`, `ValidationError`, `MetaApiError`, `NetworkError` all in `src/errors/types.ts`
- Logger with pino redact already configured in `src/cli/logger.ts`
- ESLint 9 flat config (`eslint.config.js`) instead of `.eslintrc.cjs`

### Important Notes

- **facebook-nodejs-business-sdk is CommonJS** — may need `createRequire` or a specific import approach for ESM compatibility. The Story 1.1 already uses `createRequire` pattern in `src/cli/index.ts` for loading `package.json`.
- **Account status codes** from Meta API are numeric — must be mapped to Portuguese labels
- **Instagram business account** is accessed via Page — `GET /{page-id}?fields=instagram_business_account{id,name,username}`
- **Do NOT implement upload, campaign creation, or any Epic 2 features** — this story is only about listing and configuring defaults
